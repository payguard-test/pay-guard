AI agents that pay can be tricked into paying the wrong account. pay-guard stops it on chain.

Before an agent sends money, pay-guard checks the receiver and returns allow, warn or block with reasons. A NEAR smart contract only pays receivers the checker signed, so even a hijacked agent that skips its own safety code cannot pay a blocked account, and on-chain caps limit everything else.

Three layers, so one failure is not a loss

The agent never holds the money and never holds a key that can move it directly.

01 · CHECKER

Scores the receiver

Account age and activity, whether it is a contract and if its code changed, prior payments, a shared blocklist with evidence, lookalike names and merchant attestations. Missing data never counts as safe.

02 · WRAPPER

Refuses or asks a human

Runs only with a function-call key scoped to pay. On block it signs nothing. On warn it asks a person first.

03 · CONTRACT

Enforces it on NEAR

Escrow pays only with a fresh ed25519 attestation bound to receiver, amount, nonce and expiry, under per-payment, warn and daily caps. Skipping the wrapper does not help.
